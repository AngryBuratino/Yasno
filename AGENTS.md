# AGENTS.md — правила разработки «Ясно»

## Цель проекта
«Ясно» — доступный с телефона и компьютера русскоязычный редактор для орфографии, пунктуации и деловой переписки. Главный пользовательский сценарий: вставить текст → получить предложения исправлений с объяснениями → проверить «Было / Стало» → скопировать готовую редакцию.

Рабочий сайт: https://yasno-2.vercel.app/
Репозиторий: https://github.com/AngryBuratino/Yasno
Production: Vercel, проект `yasno-2`, ветка `main`.

## Обязательные ограничения
1. **Никакого генеративного ИИ в приложении.** Не добавляй OpenAI API, другие LLM API, ИИ-чат, embeddings, собственные ключи, платные сторонние проверки или скрытые ИИ-запросы. Codex можно использовать **для разработки**, но не как часть запущенного продукта.
2. Не меняй рабочий публичный адрес, доменные настройки, существующий проект Vercel или GitHub-репозиторий.
3. Не отправляй изменения прямо в `main` и не запускай публикацию production без явного разрешения владельца. Для разработки используй отдельную ветку и Pull Request.
4. Не записывай пользовательские тексты в логи, аналитику или БД. Черновик/история/словарь — только в браузере и по выбранным пользователем настройкам. Помни, что при обычной проверке текст передаётся LanguageTool — это должно быть прозрачно для пользователя.
5. Не изменяй смысл, сроки, суммы, имена, обязательства или факты в деловых письмах. Если формулировка неоднозначна, предложи уточнение, а не выдумывай контекст. Предположения должны быть отмечены как требующие подтверждения.
6. Существующий сайт должен оставаться доступным на период разработки. Не удаляй и не заменяй текущую конфигурацию без необходимости.

## Архитектура (версия 3.2)
- `index.html`, `styles.css`, `app.js` — интерфейс без фронтенд-фреймворка.
- `api/check.js` — Vercel serverless API; LanguageTool и локальные исправления.
- `advanced-punctuation.js` — осторожные дополнительные правила пунктуации.
- `proofread-fallback.js` — общие правила для обычной проверки и делового редактора.
- `business-editor.js` — детерминированная деловая редактура без ИИ.
- `corrections.js`, `app-core.js` — применение исправлений, сравнение, словарь, шаблоны и читаемость.
- `sw.js`, `manifest.webmanifest` — PWA. При изменении ресурсов следи за инвалидированием кеша.
- `tests/*.test.js` — регрессионные тесты Node.js.

## Порядок работы Codex
1. **Первой задачей** проведи аудит проекта без изменения кода. Отдельно проверь устойчивость LanguageTool, смешение местных и удалённых исправлений, кириллические границы слов, пересекающиеся смещения, ложные срабатывания и кеширование PWA.
2. Перед изменениями воспроизведи ошибку тестом и опиши причину. Не устраняй системные проблемы бесконечным добавлением узких регулярных выражений.
3. Запускай `npm test` перед каждой сдачей. При изменениях интерфейса по возможности проверяй результат в реальном браузере на мобильной и десктопной ширине. Факт запуска тестов отличай от реальной браузерной проверки.
4. При изменении орфографии и пунктуации добавляй положительные и отрицательные примеры: правильный текст не должен портиться.
5. Сохраняй исходный текст и прозрачную возможность отклонять сомнительные исправления; не объединяй несколько рискованных изменений без контроля коллизий.
6. По итогам задачи сообщай: что изменено, почему, какие тесты пройдены, что не удалось проверить, какие остаются ограничения. Подготовь PR, а не публикацию напрямую.

## Начальные проверки качества
- Обычный режим: `Создал нам встречу на сегодня в 13:00\nПодскажите все в силе\nВсе так же нужна почта` — исправить запятую, `всё`, вопросительный знак и окончания предложений.
- Деловой режим: улучшить формулировки тех же строк, но явно отметить неоднозначность слова «почта».
- `Пришлите пожалуйста почты и я создам встречу` — проверить пунктуацию и отделение необязательных стилистических замен.
- `Я думаю что мы сможем встретиться когда у всех будет время` — проверить две запятые.
- `Сервисы такие как robokassa и продамус помогают клиентам` — проверить оборот и написание названий.
- Уже правильно написанные фразы должны оставаться неизменными.

## Не обещать невозможного
Без синтаксического анализа/LLM нельзя гарантировать уровень человеческого редактора на любых русских текстах. Предпочтительнее честно обозначить ограничения и минимизировать ложные правки, чем заявлять «идеальная пунктуация».
